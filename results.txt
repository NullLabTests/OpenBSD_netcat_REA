1. WHAT THIS FILE IS
--------------------------------------------------------------------------------
`nc` is the stock Ubuntu/Debian **netcat-openbsd** executable:

  - ELF64, x86-64, little-endian, PIE (ET_DYN), stripped (.symtab removed)
  - .note.package: {"type":"deb","os":"ubuntu","name":"netcat-openbsd",
                    "version":"1.234-1","architecture":"amd64"}
  - Embedded banner: "OpenBSD netcat (Debian patchlevel 1.234-1)"
  - Build ID: f8b823fa69cb2bcae5acf66b977262d7b7321755
  - 39,160 bytes of code/data

Conclusion: this is a distribution-packaged, unmodified-looking copy of the
OpenBSD netcat network utility. There is no evidence of custom/trojanized code;
the embedded packaging note, version banner, option table, and proxy/TLS feature
set are all consistent with the upstream `netcat-openbsd 1.234-1` package.

2. HOW IT WAS REVERSE ENGINEERED (method)
--------------------------------------------------------------------------------
1) Offline ELF layout via REA's `inspect_binary_layout` (no execution):
   sections, segments, symbols, relocations, dynamic linkage, hardening flags.
2) Ghidra 12.1.4 headless via REA's `--provider ghidra`:
   - `analyze`  -> imported the image (base 0x100000), default auto-analysis
   - `search --kind procedures/strings` -> 236 procedures, 247 strings
   - `decompile` -> pseudocode for main + every helper (25 functions)
   - `trace`     -> reference graph for the version banner
3) Cross-checks with readelf/objdump/nm/strings.
4) Upstream `netcat.c` (same patchlevel intent) used ONLY to correlate function
   roles; the binary itself is the source of truth.

Environment: Ghidra 12.1.4 + Temurin JDK 21 (Ghidra rejects JDK 25); isolated
pwntools 4.15.0 / pyelftools 0.33 / unicorn 2.1.2 for the offline provider.
